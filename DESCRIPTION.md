# Описание программы: Парсер сайтов с GUI

## Назначение

Программа предназначена для парсинга веб-сайтов с автоматическим определением селекторов и сохранением данных в Markdown и JSON форматах. Особенности:

- **Автоматическое определение селекторов** - анализ структуры страницы для поиска цен, контактов, услуг
- **Гибкая конфигурация** - поддержка индивидуальных селекторов для каждого домена
- **LLM-интеграция** - использование OpenRouter API для улучшения определения селекторов
- **Современный GUI** - графический интерфейс на PySide6 с вкладками
- **Экспорт данных** - сохранение в Markdown и JSON

## Запуск программы

### Установка зависимостей
```bash
pip install -r requirements_gui.txt
```

### Запуск GUI
```bash
python scraper_gui.py
```

### Запуск в режиме консоли (альтернатива)
```bash
python scraper_core.py <url> [--output <path>] [--config <path>] [--force-llm] [--no-json]
```

## Параметры и настройки

### GUI - вкладка "Результаты"

**Поля ввода:**
- **URL** - адрес сайта для парсинга (обязательно)

**Кнопки:**
- **Автоопределение** - запускает анализ страницы и определение селекторов без сохранения файлов. Результат отображается в дереве, а селекторы загружаются во вкладку "Селекторы" для редактирования.
- **Запустить** - выполняет полный парсинг с сохранением данных. Открывает диалог выбора пути для сохранения файлов (Markdown и JSON).

**Отображение результатов:**
- Дерево показывает: оценку уверенности (score), обнаруженные селекторы, предпросмотр данных (при автоопределении) или извлеченные данные (при полном парсинге)

### GUI - вкладка "Селекторы"

**Редактируемые поля селекторов (ввод через запятую):**
- **Цены** - CSS селекторы для элементов с ценами
- **Контакты:**
  - Телефоны - селекторы для элементов с номерами телефонов
  - Email - селекторы для элементов с email-адресами
  - Адрес - селекторы для элементов с адресом
  - Соцсети - селекторы для элементов с ссылками на соцсети
- **Услуги** - CSS селекторы для элементов с услугами/товарами

**Кнопки:**
- **Сохранить конфиг** - сохраняет селекторы в конфигурационный файл для текущего домена (автоматически определяется из URL)

### GUI - вкладка "Лог**

Отображает подробные сообщения о процессе работы программы.

## Конфигурация

### Хранение конфигураций
Конфигурации хранятся в отдельных JSON-файлах для каждого домена в директории `configs/`. Имя файла: `domain.json`

### Структура конфигурации
```json
{
  "selectors": {
    "price": [...],
    "contact": {
      "phones": [...],
      "emails": [...],
      "address": [...],
      "social": [...]
    },
    "service": [...]
  },
  "score": 0.85,
  "last_updated": "2026-03-27T10:00:00"
}
```

### Автоматическое определение
При первом парсинге домена программа автоматически определяет селекторы:
1. Анализ HTML-структуры страницы с помощью эвристик
2. Поиск паттернов (цены, телефоны, email, адреса)
3. Оценка уверенности (score) - если < 0.75, используется LLM для уточнения
4. Сохранение найденных селекторов в конфиг с оценкой

### LLM-интеграция
- Используется OpenRouter API
- Промпт на русском языке для точного извлечения данных
- Автоматический fallback на эвристики при ошибках API

## Выходные файлы

### Markdown (.md)
Структурированный отчет с данными:
- Название страницы
- Цены
- Контакты (телефоны, email, адрес, соцсети)
- Услуги
- Использованные селекторы
- Оценка уверенности

### JSON (опционально)
Полные данные в JSON-формате для дальнейшей обработки.

## Ключевые модули

- **scraper_gui.py** - графический интерфейс
- **scraper_core.py** - ядро парсинга, функция `run_parse()`
- **auto_detector.py** - автоматическое определение селекторов
- **llm_engine.py** - интеграция с OpenRouter API
- **config_manager.py** - управление конфигурациями

## Параметры функции run_parse()

```python
def run_parse(
    url: str,
    force_llm: bool = False,
    auto_detect_only: bool = False,
    output_path: Optional[str] = None,
    save_json: bool = True,
    config: Optional[Dict] = None
) -> dict:
    """
    Основная функция парсинга.

    Args:
        url: URL страницы для парсинга
        force_llm: принудительно использовать LLM даже при высоком score
        auto_detect_only: только определить селекторы, без сохранения файлов
        output_path: путь для сохранения файлов (если None, используется data/domain.md)
        save_json: сохранять ли JSON файл рядом с markdown
        config: словарь с селекторами (если None, загружается из конфига домена)

    Returns:
        Словарь с результатами: output_path, domain, score, data, used_llm, selectors, data_preview
    """
```

## Примеры использования

### Через GUI
1. Ввести URL в поле вверху
2. Перейти на вкладку "Результаты"
3. Нажать "Автоопределение" для автоматического обнаружения селекторов
4. Перейти на вкладку "Селекторы" и при необходимости отредактировать селекторы
5. Нажать "Сохранить конфиг" для сохранения изменений (опционально)
6. Вернуться на вкладку "Результаты" и нажать "Запустить"
7. В диалоге выбрать путь для сохранения файлов (Markdown и JSON)

### Через консоль
```bash
python scraper_core.py https://example.com --output ./results --force-llm
```

## Требования

- Python 3.8+
- PySide6
- beautifulsoup4
- requests
- openai (для LLM)
- lxml (опционально, для производительности)

## Обработка ошибок

- Сетевые ошибки: повторные попытки (3 раза)
- Ошибки парсинга: логируются, возвращается частичный результат
- Ошибки LLM API: fallback на эвристики
- Ошибки конфигурации: создается дефолтный конфиг

## Расширение

Для добавления поддержки новых типов данных:
1. Добавить селекторы в `auto_detector.py`
2. Обновить структуру конфига в `config_manager.py`
3. Добавить отображение в GUI
