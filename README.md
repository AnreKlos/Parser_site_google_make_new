# 🌐 KURSOR PARSER — Универсальный парсер сайтов

**KURSOR PARSER** — комплексная система для извлечения и анализа данных с веб-сайтов, состоящая из двух модулей: универсального парсера с GUI и системы аудита сайтов.

---

## 📦 Состав проекта

### 1. Универсальный парсер сайтов с GUI и LLM

Современный инструмент для извлечения данных с веб-сайтов с графическим интерфейсом, автоматическим определением селекторов и интеграцией с OpenRouter API.

**Возможности:**
- 🖥️ **Графический интерфейс** на PySide6 с удобными вкладками
- 🔍 **Автоматическое определение селекторов** — анализ структуры страницы
- 🤖 **LLM-интеграция** — использование OpenRouter API для сложных случаев
- ⚡ **Поддержка JavaScript** — рендеринг динамических страниц через Playwright
- 💾 **Экспорт данных** — Markdown и JSON форматы
- 🌐 **Генерация лендингов** — автоматическое создание сайта на основе данных

### 2. Site Audit Parser v1 (site-audit-v1/)

Система автоматического аудита веб-сайтов для оценки технического состояния и сбора бизнес-лидов.

**Возможности:**
- 📊 **Оценка технического состояния** (Tech score): доступность, HTTPS, валидность HTML
- 🎨 **Оценка устаревания дизайна** (Old score): эстетические признаки
- 🎯 **Приоритизация лидов** (Priority): комплексная оценка качества сайта
- 📋 **Сбор лидов из внешних источников**: Яндекс Карты, 2GIS
 - 📁 **Экспорт в CSV и SQLite**

## 🏗 Архитектура

После рефакторинга v2.x проект организован в слои-пакеты. Каждый слой
имеет чёткую ответственность. **При создании новых модулей следуй
этому правилу — это сэкономит часы будущего рефакторинга.**

### Правило размещения

| Слой | Ответственность | Что туда кладём | Что НЕ кладём |
|------|-----------------|-----------------|---------------|
| `core/` | Пайплайн парсинга **одного донора**. Вход: URL → Выход: structured data | Скрейперы, детекторы селекторов, парсинг блоков | Работу с БД, чтение `Lead`, бизнес-логику |
| `services/` | Бизнес-логика **над данными из БД**. Работает с моделью `Lead` и пачками лидов | Аудиторы, генераторы питчей, оркестраторы | Чистый парсинг URL без БД |
| `llm/` | Взаимодействие с LLM-моделями (OpenRouter, Vertex AI / Gemini) | LLM engine, кураторы контента | Скрейпинг, обогащение из не-LLM источников |
| `db/` | Слой данных — модели SQLAlchemy, CRUD, миграции БД | Models, async-сессии, репозитории | Бизнес-логику |
| `utils/` | Чистые утилиты без зависимостей от других слоёв | Slugify, фильтры текста, JSON-парсеры | Что-то, что зависит от БД, LLM или сети |
| `alembic/` | Миграции БД через Alembic | Базовая ревизия (`Lead + AuditLog`), последующие миграции | — |
| `config_builder/` | Сборка JSON-конфига сайта из всех источников | `build_config()`, transforms, defaults | LLM-логику, скрейпинг |
| `enrichment/` | Обогащение данных из не-LLM источников | Яндекс, Radar, extracted | LLM, работу с БД |
| `docs/migrations_archive/` | Архив ручных миграций | Старые скрипты (до перехода на Alembic) | — |

### Простой тест "куда положить файл"

- Файл принимает `url` и возвращает `dict` с данными → **`core/`**
- Файл принимает `lead_id` и пишет в БД → **`services/`**
- Файл вызывает LLM API и возвращает текст → **`llm/`**
- Файл — чистая функция без сети и БД → **`utils/`**

### Известные исключения

`site-audit-v1/` — автономный CLI-модуль аудита сайтов и сбора лидов
со своей структурой и БД. Не интегрирован с основным пайплайном,
но может использоваться отдельно как самостоятельный инструмент.
См. раздел "⚠️ Known Technical Debt".

### Конфигурация

Базовая mypy-конфигурация — `.mypy.ini` (python 3.12, `check_untyped_defs`,
`ignore_missing_imports`).

Подробнее: `docs/architecture.md`, `docs/conventions.md`, `docs/pitfalls.md`, `docs/brand-system.md`

## 📋 Использование

### Графический интерфейс парсера

1. **Введите URL** сайта в поле вверху
2. **Нажмите "Автоопределение"** — программа проанализирует страницу
3. **Перейдите на вкладку "Селекторы"** — при необходимости отредактируйте
4. **Нажмите "Запустить"** — извлечь данные
5. **Генерация лендинга** — автоматически создастся сайт-визитка

### Консольный режим парсера

```bash
python scraper_core.py <url> [--output <путь>] [--force-llm] [--use-js] [--no-json]
```

**Параметры:**
| Параметр | Описание |
|----------|----------|
| `url` | Адрес сайта (обязательно) |
| `--output` | Путь для сохранения (по умолчанию: `data/domain.md`) |
| `--force-llm` | Принудительно использовать LLM |
| `--use-js` | Использовать Playwright для JavaScript-рендеринга |
| `--auto-detect-only` | Только определить селекторы |
| `--no-json` | Не сохранять JSON |

### Сбор лидов (site-audit-v1)

```bash
# Из Яндекс Карт
python -m src.main --source yandex_maps --query "стоматология" --city "Казань" --limit 30

# Из 2GIS
python -m src.main --source 2gis --query "автосервис" --city "Москва" --limit 50

# Пакетная обработка
python -m src.main --batch data/sites.txt
```

## 🔍 Как работает парсер

### Процесс извлечения данных

1. **Загрузка HTML** — через requests или Playwright
2. **Автоопределение** — анализ структуры для поиска цен, контактов, услуг
3. **Оценка уверенности** — score от 0.0 до 1.0
4. **LLM уточнение** — если score < 0.75, используется OpenRouter API
5. **Сохранение конфига** — селекторы сохраняются для домена
6. **Извлечение данных** — применение селекторов
7. **Экспорт** — сохранение в Markdown и JSON

### Автоматическое определение

Алгоритм ищет:
- **Цены**: таблицы, блоки с классами `price`, `cost`, `tarif`
- **Контакты**: футеры, блоки `contact`, `footer`, `social`
- **Услуги**: карточки `service`, `product`, `card`, `item`

## 🐛 Устранение неполадок

### Ошибка: "OPENROUTER_API_KEY not set"
LLM функции отключены. Добавьте ключ в `.env`.

### Ошибка: "Playwright timeout"
Увеличьте `TIMEOUT_MS` или используйте `--use-js`.

### Пустые результаты
- Проверьте, не загружается ли контент через JavaScript
- Используйте флаг `--use-js`
- Проверьте селекторы во вкладке "Селекторы"

### Медленная работа
- Установите `lxml`: `pip install lxml`
- Отключите LLM для доменов с высоким score

## 🔧 Разработка

### Добавление нового типа данных

1. Определите, в каком слое должна жить логика (см. таблицу "Правило размещения")
2. Если нужен новый скрейпер/детектор — добавьте в `core/`
3. Если нужна новая LLM-обработка — добавьте промпт в `llm/`
4. Если нужна бизнес-логика над данными из БД — добавьте в `services/`

### Тестирование

```bash
# Парсер
python -m config_builder <lead_id>

# Линтер
python -m mypy config_builder/ config.py utils/text.py db/schemas.py --follow-imports=skip

# Аудит
cd site-audit-v1
pytest tests/ -v
```

### Миграции БД (Alembic)

Проект использует Alembic для управления схемой SQLite-базы.

```bash
# Создать новую миграцию после изменения моделей
alembic revision --autogenerate -m "описание изменений"

# Применить миграции
alembic upgrade head

# Откатить на одну миграцию назад
alembic downgrade -1

# Посмотреть текущий статус
alembic current

# Посмотреть историю
alembic history
```

> В dev-режиме таблицы создаются автоматически через ``create_all``.
> Чтобы переключиться на Alembic, установите переменную окружения
> ``ALEMBIC_MANAGED=1``. Тогда ``create_all`` будет пропущен,
> и схема будет управляться только через ``alembic upgrade head``.

## ⚠️ Known Technical Debt

Список известных архитектурных и технических долгов. Каждый пункт —
это запланированная работа, не баг. Документируется здесь, чтобы
не забыть и не наступить на грабли при разработке.

### Архитектурные долги

#### 2. `services/xray_auditor.py` — дублирует scraping-логику

Содержит собственные `fetch_page`, `extract_contacts`, `analyze_html`
на aiohttp. Это осознанное дублирование ради async-batch обработки,
но концептуально парсинг URL — ответственность `core/`.

**План:** когда в `core/scraper.py` появится `run_parse_async()`,
`xray_auditor` должен переиспользовать его и избавиться от дубля.

#### 3. `services/` — `sys.path.insert(0, ...)` хаки

В коде модулей `services/` встречаются ручные манипуляции с `sys.path`
для импорта соседних пакетов. Это обходной путь, который должен быть
устранён правильной настройкой пакета (через `pyproject.toml`
или `setup.py`).

**План:** настроить проект как устанавливаемый пакет, убрать
хаки с `sys.path`.

#### 4. `site-audit-v1/` — автономный модуль вне основной архитектуры

Самостоятельный пакет со своими `pyproject.toml`, `requirements.txt`,
БД и моделями (`BusinessRecord`, `AuditRecord`). Не интегрирован
с основным пайплайном. Сохраняется как рабочий CLI-инструмент
для автономного использования.

**План:** решение об интеграции scoring-логики и парсеров в основной
пайплайн отложено. Модуль не требует изменений, пока используется
отдельно.

### Долги в коде БД (db/)

#### 5. Конфликт каскадного удаления audit_logs

В `db/models.py`:
- `Lead.audit_logs = relationship(... cascade="all, delete-orphan")` —
  при удалении лида SQLAlchemy удалит связанные логи
- `AuditLog.lead_id = ForeignKey(..., ondelete="SET NULL")` —
  на уровне БД при удалении лида `lead_id` должен зануляться

Эти два механизма противоречат друг другу. На практике сработает
SQLAlchemy cascade (удалит логи), и `ON DELETE SET NULL` станет
мёртвым кодом.

**План:** определиться с семантикой. Если хотим сохранять историю
аудита при удалении лидов — убрать `cascade="all, delete-orphan"`
и оставить `SET NULL`. Если логи не нужны после удаления лида —
оставить cascade и убрать `ON DELETE SET NULL`.

#### 6. `db/database.py` — мёртвый код `_touch_lead`

Функция `_touch_lead(session, lead)` объявлена в `db/database.py`,
но нигде не вызывается. `updated_at` обновляется напрямую через
`lead.updated_at = now`.

**План:** либо начать её использовать вместо ручных обновлений,
либо удалить.

#### 7. `db/database.py` — unused import `desc`

`from sqlalchemy import select, func, desc` — `desc` импортирован,
но не используется (сортировка делается через метод `sort_col.desc()`).

**План:** убрать `desc` из импорта при следующем коммите в `db/`.
