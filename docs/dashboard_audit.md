- UI: Streamlit (`ui/admin_dashboard.py`), тёмная тема через CSS.
- Данные: прямой `sqlite3` + pandas (`load_leads()`), **не** SQLAlchemy-сессии из `db/database.py`.

## 3. KPI сверху и где строятся

Верхняя сетка 6 карточек — HTML в `main()` (~строка 781), цифры из `get_stats(df)` (`ui/admin_dashboard.py:452`) и двух локальных счётчиков:

| KPI | Источник |
|-----|----------|
| Всего | `stats["total"]` = `len(df)` |
| Квалиф. | `total - new_count` (всё, что не `status=new`) |
| С сайтом | `website` не пустой |
| Без сайта | `total - with_site` |
| Рейтинг | `df["google_rating"].mean()` |
| Отзывы | `df["reviews_count"].sum()` — это **Google** (`CLAUDE.md`) |

Вторая полоса на вкладке «База лидов» (~870–876): Всего / Audited / Pitched / No Site / New / Скрыто / Фото — тоже `get_stats()`, но уже **после** фильтров счётчики не пересчитываются (всегда по полному `df`).

`get_stats()` ещё считает `rejected_count`, но в UI он не выводится.

## 5. Реальные поля Lead для приоритета

Модель: `db/models.py` (`Lead`). Схемы `db/schemas.py` — только audit_logs, к приоритету не относятся.

| Сигнал | Есть в Lead? | В таблице / KPI? | Комментарий |
|--------|--------------|------------------|-------------|
| Сайт | `website` | да | Радар: URL соцсети не считается сайтом (`classify_url`) |
| Телефон | `phone` | нет в таблице | Place Details; есть в карточке |
| Рейтинг | `google_rating` | да | Google. Яндекс — в `data/yandex/.../card.json`, не в БД |
| Отзывы | `reviews_count` | да | Google. Для отбора кандидатов нужны Яндекс-отзывы |
| Город | `city` | да | Индекс есть; фильтр захардкожен Брянск/Москва |
| Категория | `category` | да | Радар пишет переданный `category` (дефолт `other`) |
| Дата | `created_at` | колонка «Добавлен» **сломана** | `load_leads()` не SELECT'ит `created_at` → всегда «—» |
| Статус | `status` | да | Радар: `new` / `no_website` |
| Маркетинг | нет колонки на Lead | нет | `social_links`, `emails`, `raw_reviews`; `qualification_status` в БД, дашборд не грузит. `marketing_grade` — у фото, не у лида. `notes` пишется в UI, в модели Lead **нет** (есть `audit_notes` и `ScanRegion.notes`) |

Радар дополнительно: `google_maps_url` (обязателен, иначе skip), `raw_reviews` (рейтинг ≤ 3). Яндекс URL в радаре не пишется.

## 6. Пять UX-проблем

1. **Приоритет по Google, а бизнес режет по Яндексу**  
   Почему мешает: «жирный» лид в таблице может иметь < 30 отзывов на Яндексе — ложный топ.  
   Решение: колонка «Яндекс отзывы» из `card.json` + сортировка/фильтр ≥ 30, Google оставить справочно.

2. **Нет скора приоритета, сортировка по `tech_score`**  
   Почему мешает: у `no_website` tech_score пустой → они уезжают вниз (`fillna(999)`), хотя это как раз цель продажи сайта.  
   Решение: простой score (нет сайта + отзывы + рейтинг + телефон) и сортировка по нему.

3. **Двойные KPI и «Квалиф.» врёт**  
   Почему мешает: 6 карточек сверху + 7 снизу; «Квалиф.» = не-new, включая skipped/rejected.  
   Решение: один ряд KPI **по текущему фильтру**; «Квалиф.» заменить на «Без сайта, Яндекс ≥ 30».

4. **Телефон, дата, Яндекс-сигналы спрятаны или пустые**  
   Почему мешает: нельзя быстро взять трубку и понять свежесть; «Добавлен» всегда «—».  
   Решение: SELECT `created_at`; колонки Телефон + дата; убрать мёртвый `notes` или завести поле в модели.

5. **Фильтры конфликтуют, кнопки Радар/Рентген пустые**  
   Почему мешает: radio «Кандидаты» бьёт сайдбар-статус; поиск дублируется; операции не вызывают код.  
   Решение: один поиск; radio = пресеты статуса; кнопки либо привязать к `search_and_save` / xray, либо убрать.
